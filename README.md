# 闸对

中文名：**闸对** · 前缀 `gatetwin` · 端口 **6500 / 11500**

## 骨架

**刷卡点装载 → 同卡进站出站成对物化 → 缺腿/异向/超时旁路 → 行程账与刷卡点互证**

皮：地铁/公交闸机刷卡。去皮是 **OD 成对管道 + 开腿态 + 旁路 + 行程贯验**，不是票务售票 CRUD、不是乘车码业务页、不是日结封账。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6500
# 刷卡流 → 灌「成对样例」→ 看开腿账/行程账 → 再灌「缺腿超时样例」「出站孤儿样例」→ 行程贯验
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 刷卡点 | 带卡号/站点/方向/事件时的进出闸事件 |
| 开腿账 | 已进站尚未出站的在途开腿 |
| 行程账 | 进站+出站成对后的正式行程 |
| 旁路匣 | 缺腿超时 / 出站孤儿 / 重复进站 / 负历时超漂移等 |
| 漂移审计 | 小幅负历时被窗内吸收成对的裁决留痕 |
| 行程贯验 | 成对刷卡 ↔ 行程笔数 ↔ 旁路命运 ↔ 漂移不变量互证 |

## 闸机时钟漂移（已落主链）

闸机时钟回拨使出站事件时早于进站事件时（负历时）。全局只贯彻一种口径：
**漂移秒吸收（乙）**——负历时绝对值 ≤ 站规「漂移秒」（默认 30）则成对、
历时按 0 并写漂移审计；超过才拒配旁路。被否决的甲口径是「任何负历时即旁路、
不写行程」。分叉点：出站比进站早 10 秒且漂移秒=30 时，乙有行程、甲无行程。

- 裁决与写库同成败：开腿「在途→终态」原子占位，行程/旁路同事务落库，
  并发不得旁路与行程双落；冲突整批回滚，HTTP 409，调用方重试。
- 开腿/刷卡命运同票：吸收则开腿与进出站刷卡齐「已成对」；旁路则齐「已旁路」。
- 只读裁决接口：`GET /api/漂移裁决?进站时=…&出站时=…` →
  `{进站时, 出站时, 负历时秒, 漂移秒, 口径, 命运, valid}`，不写库。
- 留痕查询：`GET /api/漂移审计`；行程账页带「漂移吸收」徽章与审计表。
- 夹具：`成对样例`（正历时）· `漂移吸收样例`（早 10 秒→成对带审计）·
  `漂移超界样例`（早 2 小时→旁路，两口径均旁路）。
- 测试：`python3 backend/tests/漂移测试.py`（口径夹具 + 裁决并发不双落）。
